## Collision screen

On 2026-09-29, live GitHub repository search for `tracewarrant in:name` and `tracewarrant in:name,description` both returned zero results. The [PyPI JSON endpoint](https://pypi.org/pypi/tracewarrant/json) returned HTTP 404, and a lookup of the proposed GitHub repository also returned HTTP 404. The hyphenated GitHub search returned `WarrantTrace` and `warrantyTracer`, neither the selected exact name. General web search for the exact name found no matching software result. This is a limited collision screen, not a reserved namespace or trademark clearance; check again immediately before publication.

FlowWitness was rejected because an [existing product uses that name](https://www.getflowwitness.com/). Historical ContextForge/agentplan alternatives already had collisions. Workload Witness was considered but TraceWarrant better captures whether evidence supports a claim.

## Public release preparation

[GitHub private vulnerability reporting](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository) provides a private reporting channel on an enabled public repository. When publishing, enable and verify that channel before replacing the pending notice in `SECURITY.md`. Do not invent a maintainer email address or publish a personal address from Git configuration.

Keep frozen documents, telemetry, predictions and schema identities unchanged. Public-facing names and the distribution/entry point change; existing Python consumers and frozen study commands keep working. Public upload remains a separate future action, and the upload-prevention classifier remains on the local candidate.
